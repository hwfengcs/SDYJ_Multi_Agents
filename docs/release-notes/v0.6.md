# v0.6 — Self-Verifying Deep Research Agent

**Status:** 🚧 in progress (alpha releases on TestPyPI)
**Branch:** `feat/v0.6-self-verifying`

v0.6 evolves SDYJ from a "well-engineered LangGraph demo" into a differentiated open-source product. The thesis is simple: agent operations are an evaluation problem, not a prompting problem. Every change in this release exists to make agent quality measurable, debuggable, and replayable.

## Theme

> A self-verifying multi-agent research framework with replayable traces, public benchmark scores, and per-call cost transparency.

## What's already shipped in 0.6.0a1

### Cost & token tracking

- New `SDYJ_Agents/utils/cost.py` ships a transparent `PRICING_TABLE` for OpenAI, Anthropic, DeepSeek, and Gemini models. Updates only require editing the table.
- `normalize_usage()` reconciles three different provider naming conventions (`prompt_tokens`/`input_tokens`/`prompt_token_count`).
- `aggregate_trace_cost()` returns `None` (not `$0.00`) when every call is unpriced, so totals stay honest.
- `InstrumentedLLM._record_call` now writes per-call `prompt_tokens_actual`, `completion_tokens_actual`, and `cost_usd` into both the `llm_calls` list and the v2 `events` stream. `finalize_trace` rolls them up into `trace.metrics`.
- The CLI `sdyj inspect-run` shows a new "LLM Calls" table with per-call cost and a tip when pricing is unknown.

### Provider usage capture

OpenAI, Claude, and Gemini wrappers now set `self.last_usage` after each successful generation (DeepSeek already did). The `last_usage` shape is the raw provider dict, so `cost.normalize_usage` can route on schema rather than hard-coded mappings per provider.

### PyPI release pipeline

`.github/workflows/publish.yml` is a two-track publisher:

- `workflow_dispatch` with `target=testpypi` → TestPyPI for alpha / beta.
- A GitHub Release event → PyPI for stable cuts.

Both use OIDC-based Trusted Publishers, so the repo never has to store a long-lived API token. See [docs/release-process.md](../release-process.md) for the one-time setup.

### Conda-first development and packaging extras

`environment.yml` is now the default local development environment and CI installs dependencies through Conda. `pyproject.toml` remains the package metadata for PyPI builds and defines `[web]`, `[mcp]`, `[benchmarks]`, and `[all]` extras so that the core install stays slim while opt-in features get their dependencies on demand.

## What's now shipped on the v0.6 branch

### Self-verifying report loop

`SDYJ_Agents/agents/verifier.py` adds the fifth agent in the LangGraph workflow. It scores each report on claim-evidence alignment, citation completeness, factual consistency, and plan coverage. When scores fall below the configured threshold, `workflow/nodes.py` routes back to the Rapporteur for a bounded revision pass and records the critique into Trace v2.

The verifier is now backed by a deterministic citation audit before the LLM
critic runs. The audit checks whether cited `[E1]` IDs exist in collected
evidence, whether key-finding bullets have valid citations, and which evidence
items were never cited. Invalid citations or unsupported key findings can force
the revise loop even when the LLM critique is lenient, and the audit metrics
also appear in benchmark summaries.

### Reflexive and parallel research

`Researcher.execute_task` now treats empty, weak, or failing search batches as a signal to reflect. It asks the LLM for up to two rewritten queries and retries once per task. The same task-level search path can execute `(query, source)` pairs concurrently through `workflow/parallel_executor.py`, with a concurrency limit so live APIs are not hammered.

### Mid-flight plan refinement

After enough subtasks complete, `WorkflowNodes._maybe_refine_plan` calls `Planner.refine_plan` once. Completed subtasks are preserved exactly, pending subtasks may be tightened, removed, or supplemented, and a `plan_refinement` trace event captures what changed.

### Streamlit Web MVP

`streamlit_app.py` delegates to `SDYJ_Agents/web/app.py`, which uses the same agents, workflow, `InstrumentedLLM`, and trace persistence path as the CLI. The MVP auto-approves the plan to avoid Streamlit rerender state issues, then renders the final report, plan, evidence cards, trace timeline, tool calls, and LLM cost table.

### Offline algorithm ablation

`docs/benchmark-results.md` records deterministic v0.5-compatible vs v0.6 algorithm-stack benchmark runs. The offline scenarios already score near ceiling, so the important result is that the new verifier/reflection/refinement/parallel trace paths keep the existing gate green while adding measurable events and metrics.

Benchmark summaries now include root-cause-oriented failure analysis for failed
thresholds, and external GAIA-style runs write `failure_analysis.json` plus
`failure_analysis.md` beside `summary.json`, `manifest.jsonl`,
`predictions.jsonl`, and `graded.jsonl`. This keeps public benchmark artifacts
auditable even when a run fails because of missing predictions, ungradeable
examples, or wrong answers.

Benchmark comparison now produces a research-style regression analysis instead
of only checking aggregate score. `--compare-summary` and `sdyj benchmark
compare` include per-metric deltas, feature/context changes, missing/new
scenarios, root-cause rollups, and top regressions/improvements. Metric-level
regressions still gate at a delta below `-0.02`, so citation, tool, or trace
degradation cannot hide behind a flat `overall_score`.

### Static trace viewer

`SDYJ_Agents/web/trace_viewer.html` is a standalone browser tool for dropping in `trace.json` or `events.jsonl`, filtering the timeline, and inspecting full event payloads. It is included in package data so PyPI installs keep the local debugging tool.

### Real MCP client adapter

`SDYJ_Agents/tools/mcp_client.py` now supports the official MCP Python SDK
transports for stdio and streamable HTTP while keeping the original
`legacy_http` REST shim. The adapter can load Claude-style `mcpServers` config
files, list tools/resources, call tools, and normalize search-like tool output
into SDYJ evidence batches.

### Deployment preflight

The repository root now has an `app.py` wrapper for hosted Streamlit runners
such as Hugging Face Spaces. The CLI also exposes `sdyj doctor`, a no-network
preflight that checks Python, provider API key presence, Tavily, optional Web /
MCP / benchmark dependencies, and MCP config parsing before a live run.

For release candidates, `sdyj release-check` and
`python scripts/release_readiness.py` bundle the local no-publish gates into one
command: doctor, pytest, ruff, synthetic external benchmark smoke, offline
benchmark determinism, MCP prerequisite checks, build, and `twine check`.
External resources such as Tavily, Docker, and GitHub MCP tokens are reported as
blockers without printing secret values.

### MCP demo scripts

`examples/mcp_demos/` includes filesystem and GitHub helpers. In default mode
they print `.env`-ready MCP variables; with `--list-tools` they launch the
server through `npx` and show the tools that SDYJ can call.

### Trace Viewer Pages workflow

`.github/workflows/pages.yml` packages `docs/` and
`SDYJ_Agents/web/trace_viewer.html` into a GitHub Pages artifact. The remaining
manual step is enabling Pages for the repository and checking the published URL.

## Migration from 0.5.0

No behavioral breakage for existing scripts. New trace fields are additive:

- `trace.metrics` gains `total_prompt_tokens`, `total_completion_tokens`, `total_tokens`, `total_cost_usd`, `priced_call_count`, `unpriced_call_count`. Old downstream consumers ignore the new keys.
- Each entry in `trace.llm_calls` gains `prompt_tokens_actual`, `completion_tokens_actual`, `cost_usd`.
- `summarize_trace()` gains the same four cost-related fields, so `diff-runs` will now show cost deltas.

If a custom downstream tool reads `trace.metrics.total_cost_usd` and gets `None`, that is correct behavior for runs where every call was made with a model not in `PRICING_TABLE`. Add the (provider, model) row to fix it.
