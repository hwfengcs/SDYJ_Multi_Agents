# v0.6 — Self-Verifying Deep Research Agent

**Status:** 🚧 in progress (alpha releases on TestPyPI)
**Branch:** `feat/v0.6-self-verifying`

v0.6 evolves SDYJ from a "well-engineered LangGraph demo" into a differentiated open-source product. The thesis is simple: agent operations are an evaluation problem, not a prompting problem. Every change in this release exists to make agent quality measurable, debuggable, and replayable.

## Theme

> A self-verifying multi-agent research framework with replayable traces, public benchmark scores, and per-call cost transparency.

## What's already shipped in 0.6.0a1

### Cost & token tracking

- New `SDYJ_Agents/utils/cost.py` ships a transparent `PRICING_TABLE` for OpenAI, Anthropic, DeepSeek, and Gemini models. Updates only require editing the table.
- `normalize_usage()` reconciles three different provider naming conventions (`prompt_tokens`/`input_tokens`/`prompt_token_count`).
- `aggregate_trace_cost()` returns `None` (not `$0.00`) when every call is unpriced, so totals stay honest.
- `InstrumentedLLM._record_call` now writes per-call `prompt_tokens_actual`, `completion_tokens_actual`, and `cost_usd` into both the `llm_calls` list and the v2 `events` stream. `finalize_trace` rolls them up into `trace.metrics`.
- The CLI `sdyj inspect-run` shows a new "LLM Calls" table with per-call cost and a tip when pricing is unknown.

### Provider usage capture

OpenAI, Claude, and Gemini wrappers now set `self.last_usage` after each successful generation (DeepSeek already did). The `last_usage` shape is the raw provider dict, so `cost.normalize_usage` can route on schema rather than hard-coded mappings per provider.

### PyPI release pipeline

`.github/workflows/publish.yml` is a two-track publisher:

- `workflow_dispatch` with `target=testpypi` → TestPyPI for alpha / beta.
- A GitHub Release event → PyPI for stable cuts.

Both use OIDC-based Trusted Publishers, so the repo never has to store a long-lived API token. See [docs/release-process.md](../release-process.md) for the one-time setup.

### Packaging extras

`pyproject.toml` now defines `[web]`, `[mcp]`, `[benchmarks]`, and `[all]` extras so that the core install stays slim while opt-in features get their dependencies on demand.

## Migration from 0.5.0

No behavioral breakage for existing scripts. New trace fields are additive:

- `trace.metrics` gains `total_prompt_tokens`, `total_completion_tokens`, `total_tokens`, `total_cost_usd`, `priced_call_count`, `unpriced_call_count`. Old downstream consumers ignore the new keys.
- Each entry in `trace.llm_calls` gains `prompt_tokens_actual`, `completion_tokens_actual`, `cost_usd`.
- `summarize_trace()` gains the same four cost-related fields, so `diff-runs` will now show cost deltas.

If a custom downstream tool reads `trace.metrics.total_cost_usd` and gets `None`, that is correct behavior for runs where every call was made with a model not in `PRICING_TABLE`. Add the (provider, model) row to fix it.
